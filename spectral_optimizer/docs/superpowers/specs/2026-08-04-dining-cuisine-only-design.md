# 餐饮光色菜系单一入口修订设计

本修订替代《餐饮光色菜式视觉分类与菜系标签设计》中“应用场景与菜系并列选择”和“全部图片必须预先存入项目”的相关内容。

## 1. 控制结构

餐饮光色只保留“菜系/餐饮类型”一个业务分类入口。页面不再显示应用场景选择。

顶部条件依次为：

1. 菜系/餐饮类型
2. 色点模式
3. 优化策略
4. 增强程度

每个菜系配置参与优化的菜式类型、权重、推荐CCT、适用色温范围、推荐Duv和浅色控制菜式。

色点模式保留两项：

- 保持当前色点
- 采用菜系推荐

## 2. 优化数据流

菜系直接产生优化请求：

- `cuisineProfileId`
- `cuisineProfileName`
- `materialIds`
- `profileOverridesByMaterialId`
- `targetCct`
- `targetDuv`
- `cctRange`

优化器缓存键包含菜系、增强程度、色点模式、目标CCT、目标Duv、通道和菜式集合。连续切换菜系时继续从统一原始通道基线计算。

返回结果使用：

- `recommendedTargetApplied`
- “菜系推荐色点”
- “菜系加权得分”

旧的`diningProfileId`、`diningProfileName`和`sceneTargetApplied`退出餐饮运行链路。

## 3. 菜式图片

12类菜式均使用具体成品菜照片。主图来自Wikimedia Commons的直接缩略图地址，允许浏览器画布读取和优化预览计算。

每个图片配置同时包含：

- `file`：Wikimedia上传服务器的具体图片地址
- `sourcePage`：作者和许可信息页面
- `fallbackFile`：项目内本地备用图

缩略图采用“具体菜式图 + 本地备用图”双层背景。远程图片加载失败时，浏览器显示本地备用图。

优化前后画布优先读取具体菜式图。远程读取失败时自动切换本地备用图。页面不会出现空白卡片或“图片待补齐”占位。

## 4. 验收条件

- 页面不存在应用场景选择器。
- 17个菜系/餐饮类型都包含推荐CCT、Duv和参与菜式。
- 12张菜式图片地址均可在浏览器中解码并允许画布像素读取。
- 12类卡片无图片占位状态。
- 网络异常时本地备用图可正常显示。
- 保持当前色点与采用菜系推荐两种模式均可运行。
- 连续切换菜系和增强程度时不继承上一轮输出配方。
- 餐饮专项和完整项目回归全部通过。
